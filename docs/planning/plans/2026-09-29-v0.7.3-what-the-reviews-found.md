# v0.7.3 — What the reviews found — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking. TDD throughout: every step that changes behaviour starts with a test that is **run and seen failing**.

**Goal:** Close #172, #173 and #194:

- A CalDAV block that fails is shown on both UIs and survives a reload.
- A save that skipped the probe is logged.
- One predicate decides and words a refused save.
- The address lookup suggests ports that answer from this host.

**Architecture:** Nothing new at the architecture level. Three seams change:

- `shared/settings-api.ts` loses a predicate.
- `src/settings-routes.ts` gains a one-shot notice map and a log line.
- `src/autoconfig.ts` ranks candidates per service and pre-checks them with a connect-only `reachable()` that is injectable like the other `AutoconfigDeps`.

The wizard (`oauth/src/setup-routes.ts`) reads the `201` it already receives.

**Spec:** `docs/planning/specs/2026-09-29-v0.7.3-what-the-reviews-found.md`. Read it first; this plan argues from it. Line numbers there are as of `f2cdbd6` — read the tree, they drift.

## Global Constraints

- **PR-only onto a protected `main`.** Every `gh` call needs `--repo YannicHock/claude-mail-mcp`.
- **No `Co-Authored-By` trailer, no "Generated with Claude Code" footer.**
- PR bodies via `--body-file` from a quoted heredoc, never `--body "..."`.
- CI: `gh run list --repo … --branch <b>` → `gh run watch <id> --repo … --exit-status`. Not `gh pr checks --watch`.
- **Merge style:** multi-commit → merge commit `merge: <topic>`; single commit → rebase-merge.
- Integration suite: only one checkout at a time. A port bind error is contention: wait and retry, never skip the suite.
- Log lines carry booleans, ids and host:port pairs. Never an address, a local part or a password.
- `CHANGELOG.md` `[Unreleased]`: Added, Changed, Fixed, in that order.

### Task 6: the lookup ranks candidates and keeps the one that answers (#194)

Files: `src/autoconfig.ts`, `src/lookup-reachability.ts` (new), `shared/settings-api.ts` (budget), `src/settings-routes.ts` (logger passed through, if the lookup is called there), `test/unit/autoconfig.test.ts`, `test/unit/lookup-reachability.test.ts` (new), `oauth/test/...` (the derived-budget test, if it pins the number).

- [ ] Red, `lookup-reachability.test.ts`. `reachable({host, port, socketType}, timeoutMs): Promise<boolean>` is checked against local servers:
  - a `net.Server` writing `220 hi\r\n` → true for STARTTLS
  - a `net.Server` that accepts and says nothing → false within the timeout
  - a closed port → false
  - a `tls.Server` with a throwaway self-signed cert:
    - true for SSL when the test passes that cert as `ca` through an options parameter
    - **false** without it

    The handshake is verified normally, `servername` = host, and TLS verification is never disabled. A candidate whose certificate would fail at the real connection must not win at the lookup.
  - an IMAP greeting `* OK` → true
- [ ] Red, `autoconfig.test.ts`, using the existing fake deps plus `reachable`:
  - ISPDB `gmail.com` document with only 465 SSL; 465 unreachable, 587 reachable → the suggestion is 587, `tls: false`, STARTTLS.
  - Both reachable → 465.
  - Neither → 465.
  - A domain in no table with one candidate → unchanged, and `reachable` is called once or not at all.
  - SRV with both `_submissions` and `_submission` → both reach `reachable`.
  - A candidate resolving to `10.0.0.5` → `reachable` is never called for it.
  - Five SMTP blocks → at most 4 probed.
  - `reachable` never settles → `lookupMailboxSettings` resolves in ≤ 13 s + 250 ms. Use the module's injectable timing so the test does not actually wait 13 s, if it has one; otherwise shorten via `LookupOptions`.
  - IMAP gets the same treatment: one case.
- [ ] Green:
  - `parseClientConfig` keeps its public return shape. An internal `rankClientConfig` returns ranked lists, and `best()` becomes the sort.
  - `fromSrv` collects both submission records.
  - `presetCandidates(address)` maps `PROVIDER_ADVICE.domains` → `MAIL_PROVIDERS` by id.
  - `choose(ranked, deps.reachable, budget)` probes in parallel, capped, with private addresses skipped via `resolveAddresses` + `isPublicIp`.
  - `CONNECTOR_AUTOCONFIG_BUDGET_MS = 13_000`, with a comment splitting it into discovery 10 s plus probe 3 s, both named constants.
  - One `info` log line per service, if the lookup has a logger. If it has none, return the choice and log at the route.
- [ ] Unit suites in both packages (the wizard's derived `LOOKUP_TIMEOUT_MS` test). Commit: `feat(autoconfig): suggest the mail ports that answer from this host (#194)`.
